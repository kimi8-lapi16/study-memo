## Googleパスワードマネージャーに脆弱性、パスキーを乗っ取る「Pass-the-Passkey」攻撃

Palo Alto NetworksのUnit 42は、Googleパスワードマネージャーの同期機能を悪用し、パスキーで保護されたアカウントを乗っ取れる3種類の攻撃手法「Pass-the-Passkey」を報告した。

セキュリティインシデント・脆弱性案件。基本形はマルウェアに感染したPCのTPMから鍵情報を盗み出し正規のChrome認証手続きを装う手口で、本人確認が不十分なサービスでは指紋認証やPIN入力なしに別端末からのログインを許してしまう。端末の再登録手続きを悪用して不正な認証情報を長期間登録し続ける発展形「Silver」、保存済みパスキーを複数まとめて復号できるマスターキーをChromeのメモリから丸ごと盗み出す「Golden」もある。前提としてTPM搭載Windows PCのマルウェア感染が必要で、Unit 42はパスキーそのものの暗号方式が破られたわけではないと強調しつつ、サービス提供者側での本人確認情報の検証強化や不審な端末再登録パターンの検知を呼びかけている。

## 今日のTips: StrictModeがeffectを2回実行するのはバグを"あぶり出す"ため

Reactの`<StrictMode>`配下では、開発環境限定でエフェクトが「セットアップ→クリーンアップ→セットアップ」の順に2回実行される。これはReact 18以降の挙動で、狙いはクリーンアップの書き忘れを早期に発見すること。クリーンアップを実装し忘れたエフェクトは、2回目のセットアップ時点で購読やタイマーが二重に張られてしまうため、開発中に不具合として気づける。

```tsx
useEffect(() => {
  const connection = createConnection(url);
  connection.connect(); // 1回目のセットアップ
  return () => connection.disconnect(); // クリーンアップ
  // ここでセットアップが再実行される
}, [url]);
```

<Tip label="▶ 補足">
2回実行されるのはコンポーネント本体やuseState/useMemoの初期化関数、effect、コールバックref関数など「純粋であるべき」処理のみで、イベントハンドラ内のコードやsetTimeoutのコールバックは対象外。本番ビルドでは1回しか実行されない。
</Tip>
