## 35年物の暗号チャレンジ「RSA-260」、AI企業エンジニアが素因数分解に成功

AI企業CognitionのエンジニアであるEric Lu氏は9月3日、SNS上で260桁の数「RSA-260」の素因数の一つを特定したと発表した。論文ではなく「divides RSA-260」という一言と130桁の数字を投稿する形での公開だった。

新技術紹介案件。RSA-260は1991年に公開された「RSA Factoring Challenge」の一つで、35年間未解決のまま最大記録として残っていた。RSA暗号は「2つの大きな素数の掛け算は簡単だが逆算は極めて難しい」という原理に基づくが、現行のRSA暗号は2048ビット以上を用いておりRSA-260の倍以上の桁数があるため、直接的な脅威にはならない。暗号研究者からは「量子コンピュータとは無関係」との指摘も相次いだ。

## 今日のTips: Reactのkeyにindexを使うと、並び替え・削除でstateがズレる

Reactのリストレンダリングでは、各要素にstateを識別するための`key`を渡すのが基本だが、配列のインデックスをそのまま`key`にするのは公式ドキュメントで明確に非推奨とされている。

> The order in which you render items will change over time if an item is inserted, deleted, or if the array gets reordered. Index as a key often leads to subtle and confusing bugs.

例えば、入力欄を持つリストでindexをkeyにしていると、先頭の要素を削除したときに2番目以降の要素がそれぞれ1つ前のindexに繰り上がり、Reactは「同じ要素の中身が変わった」と誤認してDOMやstateを使い回してしまう。

```jsx
// NG: 削除・並び替えでstateが別要素に紐付く
items.map((item, i) => <Row key={i} item={item} />)

// OK: 要素固有の安定したIDを使う
items.map((item) => <Row key={item.id} item={item} />)
```

対策として、公式ドキュメントはデータベースのIDや`crypto.randomUUID()`など、要素ごとに変わらない安定した一意のIDを`key`に使うことを推奨している。

参考: [React docs: Rendering Lists](https://react.dev/learn/rendering-lists)
