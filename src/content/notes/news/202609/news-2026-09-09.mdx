## NEC、量子コンピュータの実機開発を中止 実用化への課題重く

NECが量子コンピュータの実機開発を中止していたと、日本経済新聞と時事通信が9月7日に報じた。

業界動向案件。中止は今年3月末で、実用化に向けて「有力な方式が定まらないなど課題が多く、ハード開発の継続は費用対効果が見合わない」と判断したとみられる。NECは1999年に超電導量子ビットを世界で初めて実現し、Google・IBMが採用する方式の源流を生み出した先駆者だったが、今後は実機開発から転換し、量子力学を活用して複雑な計算を行う量子コンピューティング技術の開発・サービスに注力するという。

## ベトナム関連のAPISデータベースから2.2億件の渡航者記録が露出

ベトナムに関連するAdvance Passenger Information System（APIS）データベースから、2億2000万件超の乗客・乗務員記録が外部から到達可能な状態になっていたことが判明した。

セキュリティインシデント・脆弱性案件。露出していたのは2017年1月から2026年4月にかけての記録で、氏名・生年月日・国籍・パスポート番号・有効期限・フライト情報などが含まれる。直接アクセスはHTTP 401で遮断されていたが、クラウド経由の別経路からデフォルト認証情報でアクセスできる状態だったという。発見したKinryu Labsによれば、システムはハノイのベトテル系IPアドレス空間でホストされていた。今年6月3日の発見後、ベトナム当局・各国CERT・航空会社への報告を経て、6月8日にアクセスが遮断されている。

## 今日のTips: NestJSのGuardは、InterceptorやPipeより先に実行される

NestJSのリクエスト処理パイプラインでは、Middleware → Guard → Interceptor → Pipe → ハンドラー、という順序で実行される。公式ドキュメントには「Guards are executed after all middleware, but before any interceptor or pipe.」と明記されている。

```ts
// 実行順序: Middleware → Guard → Interceptor → Pipe → Handler
@UseGuards(AuthGuard)       // 2番目に実行
@UseInterceptors(LogInterceptor) // 3番目に実行
@UsePipes(ValidationPipe)   // 4番目に実行
findAll() {}
```

<Note>
Pipeでリクエストボディを変換・検証してからGuardで認可判定したい、という発想は成立しない。Guardの時点ではPipeによる変換前の生の値しかExecutionContextから取得できないため、認可ロジックが変換後の値に依存していると意図通りに動かない。
</Note>

参考: [NestJS Documentation - Guards](https://docs.nestjs.com/guards)
