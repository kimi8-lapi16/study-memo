## 今日のTips: PostgreSQLの制約追加、`NOT VALID`+`VALIDATE CONSTRAINT`でロックを弱められる

外部キーやCHECK制約を`ALTER TABLE ADD CONSTRAINT`で追加すると、既存行の検証のためコマンドがコミットされるまで他の更新がロックアウトされる。`NOT VALID`を付けるとテーブルスキャンをせずに即座にコミットでき、後から`VALIDATE CONSTRAINT`で検証すれば、検証時のロックは`SHARE UPDATE EXCLUSIVE`(外部キーなら参照先テーブルへの`ROW SHARE`も)で済み、他の更新と並行実行できる。

```sql
-- 1. NOT VALIDで即座にコミット(テーブルスキャンなし)
ALTER TABLE distributors ADD CONSTRAINT distfk
  FOREIGN KEY (address) REFERENCES addresses (address) NOT VALID;

-- 2. 別トランザクションで検証(SHARE UPDATE EXCLUSIVEロックのみ)
ALTER TABLE distributors VALIDATE CONSTRAINT distfk;
```

<Tip>
`NOT VALID`を付けた時点で新規のINSERT/UPDATEには制約が適用される。既存データに違反があっても、`VALIDATE CONSTRAINT`が成功するまでの間に落ち着いて修正できる。
</Tip>
