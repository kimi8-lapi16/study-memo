## 今日のTips: `startTransition`は`await`の後の状態更新を自動ではトランジション扱いにしない

Reactの`startTransition`（および`useTransition`）は、コールバック内で同期的に呼び出した`set`関数の更新だけをトランジションとしてマークする。`async`関数を渡して`await`を挟むと、`await`より後ろで呼ぶ`set`関数の更新はトランジションの対象外になり、通常の緊急な更新として扱われてしまう。

```jsx
function updateName(name) {
  startTransition(async () => {
    const error = await updateNameOnServer(name);
    if (error) {
      setError(error); // ここはトランジション扱いにならない
      return;
    }
    // await の後で更新をトランジション扱いにするには
    // 追加でstartTransitionにラップする必要がある
    startTransition(() => {
      setName(name);
    });
  });
}
```

<Note>
公式ドキュメントも「これは既知の制限で、将来的に修正予定」としている現状の仕様。`await`後の更新を含めてローディング表示を制御したい場合は、`await`の後ろの`set`呼び出しをもう一段`startTransition`でラップする必要がある。
</Note>
