## Java 27正式リリース、全環境でG1 GCがデフォルトに

Oracleは9月15日、Javaの最新版「Java 27」を正式リリースした。

開発ツール・言語・OSS動向案件。目玉はJEP 523により、G1ガベージコレクタがすべての環境で既定になった点。これまでCPU1個・物理メモリ1792MB未満の環境では軽量なSerial GCが既定だったが、性能改善が進んだG1に統一される。またJEP 527により、TLS 1.3向けにポスト量子暗号を組み合わせたハイブリッド鍵交換が既定で有効になり、既存アプリのコード変更なしに「Harvest Now, Decrypt Later」(現在の暗号通信を保存し将来の量子コンピュータで復号する攻撃手法)への耐性を高められる。このほかコンパクトオブジェクトヘッダー(64bit環境で96bitから64bitへ削減)、構造化並行処理やVector APIのプレビュー更新なども含まれる。なおJava 27はLTS(長期サポート)版ではなく、サポート期間は2027年3月までの半年間にとどまる。

## 今日のTips: Prismaのカラムリネームは既定でDROP+CREATE、そのままではデータが失われる

Prismaスキーマでフィールド名を変更して`prisma migrate dev`を実行すると、既定では旧カラムをDROPし新カラムをCREATEするマイグレーションが生成される。公式ドキュメントも「renaming a field in the schema results in a migration that will: CREATE a new column ... DROP the existing column ... and the data in that column」と明記しており、見た目はリネームでも実体は「別カラムへの置き換え」で、既存データが失われる。

```sql
-- 既定で生成されるSQL(データが失われる)
ALTER TABLE "User" DROP COLUMN "name", ADD COLUMN "fullname" TEXT;

-- RENAME COLUMNに書き換えれば既存データを保持できる
ALTER TABLE "User" RENAME COLUMN "name" TO "fullname";
```

<Note>
`prisma migrate dev --create-only`でマイグレーションファイルを生成するとDBにはまだ適用されないため、この段階でSQLを上記のように手動編集してから`prisma migrate dev`を実行すれば、データを保持したままリネームできる。
</Note>

参考: [Prisma Documentation: Customizing migrations](https://www.prisma.io/docs/orm/v7/prisma-migrate/workflows/customizing-migrations)
