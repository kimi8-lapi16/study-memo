## 今日のTips: NestJSの例外フィルター、他と違い「ルート→コントローラー→グローバル」の順で解決される

NestJSのリクエストライフサイクルでは、Middleware→Guards→Interceptors→Pipesの順に処理が進み、これらはいずれも「グローバル→コントローラー→ルート」の順で解決される。ところが例外フィルターだけはこの原則の例外で、公式ドキュメントは「Filters are the only component that don't resolve global first」と明記しており、実際には**ルートレベル→コントローラーレベル→グローバル**の順で解決される。

```typescript
@Controller('cats')
@UseFilters(ControllerLevelFilter) // 2番目に評価される
export class CatsController {
  @Get()
  @UseFilters(RouteLevelFilter) // 最初に評価される
  findAll() {
    throw new HttpException('Forbidden', 403);
  }
}
// main.ts の app.useGlobalFilters(GlobalFilter) は最後に評価される
```

<Tip>
Guards/Interceptors/Pipesの感覚で「グローバルが最優先」と思い込むと、ルート/コントローラーの個別フィルターがグローバルの共通処理(ロギング・レスポンス整形など)より先に例外を捕まえてしまい、想定した共通処理が効かないことがある。
</Tip>
