セキュリティインシデント・脆弱性案件。例えば"funding"のような金融関連の語に不可視文字を挟んで"fun[不可視文字]ding"のように変形し、検出ワードとして認識されにくくする。2月9日から5月中旬にかけて観測され、ピーク時には1日あたり237万件のメッセージに達し、148ドメインが全体の96%を占めたという。Microsoftは対策として、メールフィルタリングの前段階、およびAI支援システムに渡す前段階の両方で、Unicodeタグ文字など不可視のコードポイントを正規化・除去することを推奨している。

## 今日のTips: TypeScriptの「Excess Property Checks」、オブジェクトリテラル直書きの時だけ働く

TypeScriptは、オブジェクトリテラルを関数引数などに直接渡すとき、対象の型に存在しないプロパティがあればエラーにする「Excess Property Checks（過剰プロパティチェック）」を行う。ところが、いったん変数に代入してから渡すとこのチェックは働かない、という落とし穴がある。

```ts
interface SquareConfig {
  color?: string;
  width?: number;
}

declare function createSquare(config: SquareConfig): void;

createSquare({ colour: "red", width: 100 }); // エラー: 'colour' は存在しない

const opts = { colour: "red", width: 100 };
createSquare(opts); // エラーにならない（共通プロパティwidthがあるため）
```

<Note>
変数経由で回避できてしまうのは、構造的型付け（structural typing）上は`colour`のような余剰プロパティを許容するのが本来の動作だから。過剰プロパティチェックはあくまで「タイポの早期発見」のための追加チェックであり、オブジェクトリテラル直書きの場合にだけ働く点を覚えておくと、スペルミスが変数経由ですり抜ける事故を理解しやすい。
</Note>

参考: [TypeScript Handbook: Object Types - Excess Property Checks](https://www.typescriptlang.org/docs/handbook/2/objects.html)
