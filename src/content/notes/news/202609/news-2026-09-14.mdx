## Microsoft、Rustを社内の最上位言語「Tier 1」に格上げ

Microsoftは9月14日、プログラミング言語Rustを社内のソフトウェア開発における「Tier 1」言語に格上げしたと発表した。

開発ツール・言語・OSS動向案件。同社Rustツールチームのプリンシパルエンジニアが明らかにしたもので、Tier 1指定は安全なツールチェーン・ビルド・開発環境・ワークフロー・プラットフォーム統合を含む全社的なソフトウェアライフサイクル要件をRustが満たしたことを意味し、C++やC#、TypeScriptと並ぶ位置づけになる。背景には、RustコンパイラとMicrosoft VC++の相互運用を実現する独自基盤「rustc_codegen_utc」の開発があり、既存のMSVCエコシステムをRustからも利用できるようにした。これによりファームウェアからアプリケーション層まで幅広い採用が可能になり、社内では既に100以上のプロジェクトが本番環境で採用、その数は週単位で増加しているという。

セキュリティインシデント・脆弱性案件（最大3件枠）。Brevoは9月9日、120アカウントが不正アクセスを受けたと公表しており、攻撃者はTrezorを含む複数の顧客アカウントを悪用して詐欺メールを送信した。Trezor宛を装ったフィッシングメールは「STM32マイクロコントローラーの脆弱性を悪用した資金盗取の危険性がある」との偽の緊急セキュリティ警告を装い、受信者にウォレットのバックアップ情報を入力させる悪意あるアプリへ誘導する内容だった。影響を受けたメールアドレスは約34.7万件、実際に不審なリンクをクリックしたユーザーは約2,500人という。Trezorは検知から20分以内に悪用ドメインを削除し、Brevo側のアカウントも停止させたことで被害拡大を防いだとしている。

## 今日のTips: PostgreSQLの外部キー、参照元列にインデックスが無いと親の更新・削除で遅くなる

PostgreSQLで外部キー制約（REFERENCES）を張るとき、参照先（親）テーブル側の列には主キー等で通常インデックスが付いているが、参照元（子）テーブル側の列には自動でインデックスは作られない。公式ドキュメントは「参照先列が頻繁に変更される場合、参照アクションを効率的に実行できるよう参照元列にインデックスを作成するのが賢明」と明記している。

```sql
CREATE TABLE distributors (
  did  integer PRIMARY KEY,
  name varchar(40) NOT NULL
);

CREATE TABLE films (
  code char(5) PRIMARY KEY,
  did  integer REFERENCES distributors(did)
);

-- 子テーブル側にも明示的にインデックスを作成する
CREATE INDEX idx_films_did ON films (did);
```

<Note>
インデックスが無くても外部キー制約自体は機能する（挿入・更新時の整合性チェックには親テーブル側のインデックスが使われる）。問題になるのは親テーブルの行をUPDATE/DELETEしたときで、子テーブル側に対応行が残っていないか確認するスキャンのコストが、子テーブル側のインデックスの有無で大きく変わってくる。
</Note>
