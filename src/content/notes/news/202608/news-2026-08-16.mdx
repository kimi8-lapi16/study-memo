## Anthropic、「Claude」の生成文に電子透かしを実装 見た目を変えずAI生成を判定

Anthropicは8月14日、「Claude」が生成するテキストにAI生成であることを示す電子透かしを組み込んだ仕組みを公開した。文章に不可視文字や追加トークンを挿入せず、既存の見た目のまま生成元を判定できるという。

AI・LLM動向案件。単語の生成時に複数の候補がある場合、内部の「鍵」と直前の単語列を使って一見ランダムに見える選び方で単語を選択し、そのパターンから生成元を後から検証できる仕組み。追加コストやトークン増加は発生しない。軽微な編集では透かしが残るが、全文を書き換えるような大幅な改変では機能しなくなる可能性があるとしている。全世界のClaudeの出力に順次適用し、8月2日以前のレガシーモデルについても数カ月かけて対応する予定。

## 今日のTips: NestJSのリクエストは「Middleware→Guard→Interceptor→Pipe→ハンドラ」の順で処理される

NestJSでリクエストがどのコンポーネントをどの順で通過するのか、感覚で把握している人は多いが、公式ドキュメントには明確な順序が定義されている。

```
Middleware → Guard → Interceptor（コントローラ呼び出し前）
  → Pipe → コントローラ（ハンドラ）→ Service
  → Interceptor（レスポンス側）→ Exception Filter
  → レスポンス
```

各段階は基本的に「グローバル → コントローラ → ルート」の順で解決される（Interceptorのレスポンス側だけは逆に「ルート → コントローラ → グローバル」の順）。ルートパラメータに複数のPipeを設定した場合は、最後のパラメータに紐づくPipeから先に実行される点も見落としやすい。

<Tip label="▶ 補足">
Guardは「認可判断」、Interceptorは「前後処理の差し込み」、Pipeは「入力の検証・変換」という役割分担のため、この順序は「まず入れるかどうかを判断し（Guard）、次に処理を横取りできるようにし（Interceptor前段）、最後に入力データを整形する（Pipe）」という設計意図の表れと理解すると覚えやすい。
</Tip>
