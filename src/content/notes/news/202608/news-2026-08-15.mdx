## OpenAI、GPT-5.6 Solを最大14倍高速化する「Ultrafast」モードを発表

OpenAIは8月13日、AIモデル「GPT-5.6 Sol」の高速動作モード「Ultrafast」を発表した。品質を損なわずに標準モード比で最大14倍という生成速度を実現するという。

AI・LLM動向案件。半導体メーカーCerebrasとの提携が高速化の鍵で、ウエハー1枚を丸ごと1個のプロセッサとして使い44GBのSRAMを搭載する専用チップによってデータ転送のボトルネックを解消した。生成速度は毎秒750トークンに達し、難易度の高い専門知識問題「Humanity's Last Exam」全2500問の処理でも、Anthropicの「Claude Fable 5」が78時間27分を要したのに対し約11時間11分で同等の精度を達成したとする。まずはOpenAI API経由で一部顧客向けの限定プレビューとして提供を始め、処理能力の向上に伴い対象を順次拡大する予定。

## 北朝鮮Lazarusが悪用したWindows WinSockのゼロデイ脆弱性、Microsoftが修正

Microsoftは8月11日（現地時間）の月例セキュリティ更新で、Windows Ancillary Function Driver for WinSock（afd.sys）の権限昇格の脆弱性「CVE-2026-68820」を修正した。同脆弱性は修正前から北朝鮮Lazarus集団による悪用が確認されていた。

セキュリティインシデント・脆弱性案件。afd.sysはWindowsのソケット操作を司るカーネルモジュールで、今回の脆弱性はuse-after-free型の欠陥。ローカル権限を持つ攻撃者が競合状態を悪用することでSYSTEM権限を取得できる。LazarusはOperation Dream Jobキャンペーンの一環として7月初旬から少なくとも5週間、偽の採用オファーで防衛・航空宇宙分野の企業を標的にこの脆弱性を悪用し、EDRのテレメトリを無効化する「FudModule」ルートキットや「Troy」バックドアを展開していた。JPCERT/CCも8月12日付で今回のMicrosoft月例更新に関する注意喚起を出し、本脆弱性が悪用されていることを確認済みとして早急な適用を呼びかけている。

## Clopランサムウェア、PTC Windchill/FlexPLMの脆弱性悪用でShellなど大手企業からデータ窃取

ロシア系とされるランサムウェアグループClopが、PLM（製品ライフサイクル管理）製品「PTC Windchill」「FlexPLM」の脆弱性を悪用し、Shellをはじめとする複数の大手企業からデータを窃取したと主張していることが8月14日までに明らかになった。

セキュリティインシデント・脆弱性案件。悪用されたのは不適切な入力検証の脆弱性「CVE-2026-12569」で、パッチは6月17日に公開済み、CISAも6月25日に既知の悪用された脆弱性（KEV）カタログへ追加し連邦機関に3日以内の適用を指示していた。Clopは自らのリークサイトで、Shellからエンジニアリング図面や施設テスト報告書など約89GB、Philipsから設計図など約13.5GBを窃取したと主張しており、GEやFiservなど計約50社から情報を得たともしているが、この件数はClop側の主張で第三者による検証はされていない。Shellは「潜在的なインシデント」として調査中であることを認めている。

## 今日のTips: PostgreSQLのNOT VALID制約、テーブルスキャンなしで即座に制約追加できる

大きなテーブルにCHECK制約や外部キー制約を`ALTER TABLE ... ADD CONSTRAINT`で追加すると、既存の全行を検証するテーブルスキャンが走り、その間`ACCESS EXCLUSIVE`ロックでテーブル全体がブロックされてしまう。

```sql
-- 通常の追加: 全行スキャン + ACCESS EXCLUSIVEロック
ALTER TABLE distributors
  ADD CONSTRAINT distfk FOREIGN KEY (address)
  REFERENCES addresses (address);
```

`NOT VALID`オプションを付けると、既存行の検証をスキップして制約をすぐに有効化できる（以降の挿入・更新には即座に強制される）。外部キーの場合、通常の`ADD FOREIGN KEY`と同じ`SHARE ROW EXCLUSIVE`ロックで済み、テーブルスキャンも発生しないためコミットが速い。

```sql
-- Step 1: スキャンなしで制約を追加（ロック時間を最小化）
ALTER TABLE distributors
  ADD CONSTRAINT distfk FOREIGN KEY (address)
  REFERENCES addresses (address) NOT VALID;

-- Step 2: 別トランザクションで既存行を検証
ALTER TABLE distributors VALIDATE CONSTRAINT distfk;
```

<Tip label="▶ 補足">
`VALIDATE CONSTRAINT`は`SHARE UPDATE EXCLUSIVE`ロックのみで動作し、他トランザクションによる行の挿入・更新をブロックしない（新規行はStep 1の時点で既に制約が強制されているため、検証対象は既存行だけでよい）。大テーブルへの制約追加はこの2段階に分けるのが定石。
</Tip>
