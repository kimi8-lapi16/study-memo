## Google検索結果のリンクが「google.com/goto」経由に スクレイピング対策の一環

Googleは検索結果のリンク先URLを、直接のリンクではなく「google.com/goto」というパススルーURL経由に置き換える変更を8月第1週から大規模展開していることが8月28日までに明らかになった。

新技術紹介案件。従来のクライアント側リンクをサーバーサイドリダイレクトに置き換えるもので、Googleは「進化する不正行為に対する技術的対策」とコメントしており、AIボットやサードパーティー製ツールによる検索結果のスクレイピング防止が主な狙いとみられる。一般ユーザーへの体感的な影響は少ないが、マウスオーバー時に表示されるリンク先がパススルーURLになるほか、サードパーティー製のトラッキングツールが影響を受ける可能性がある。

出典: [GIGAZINE](https://gigazine.net/news/20260828-google-search-goto-tracking-parameters/)

## 医薬品卸大手McKesson、ShinyHuntersによる不正アクセスで情報漏えい

米医薬品卸大手McKessonは8月28日、SECへの8-K様式の報告で、従業員を狙ったビッシング（音声フィッシング）攻撃を受けOkta SSO認証情報が侵害され、Salesforce・Snowflake環境への不正アクセスが発生したと開示した。

出典: [BleepingComputer](https://www.bleepingcomputer.com/news/security/mckesson-discloses-breach-after-shinyhunters-claims-patient-data-theft/)

## 今日のTips: `useOptimistic`で、サーバー結果を待たずにUIを即座に更新する

React 19で追加された`useOptimistic`フックを使うと、サーバーアクションの完了を待たずに、成功した前提でUIを先に更新できる。

```tsx
const [optimisticName, setOptimisticName] = useOptimistic(name);

function handleClick() {
  startTransition(async () => {
    setOptimisticName('新しい名前'); // 即座に反映
    const result = await updateName('新しい名前');
    setName(result); // サーバー結果で確定
  });
}
```

`setOptimisticName`の呼び出しは、`startTransition`内またはAction内でなければならない（それ以外で呼ぶと警告になる）。Actionが失敗し、かつ元の`name`が更新されなかった場合は、UIが自動的に楽観的な値から元の値へロールバックされる。

<Tip label="▶ 補足">
複数の更新が絡む場合は第2引数にリデューサーを渡せる。Action実行中に親のstateが変わっても、最新のstateに対して楽観的更新が適用される。
</Tip>
