## TikTok、児童プライバシー訴訟で米司法省と4億ドルの和解

米司法省とTikTokは8月21日、児童オンラインプライバシー保護法（COPPA）違反を巡る訴訟について、総額4億ドル（約640億円）の支払いで和解したと発表した。

訴訟・トラブル案件。司法省は2024年8月、TikTokと親会社ByteDanceを「13歳未満と把握している子どもにも通常アカウントの作成を認め、保護者の同意なく個人情報を収集・保持していた」として提訴していた。和解金は即座に支払う3億ドルと、前身の動画サービスMusical.lyに関する2019年の同意判決が取り消された時点で追加支払いとなる1億ドルの2段階構成。司法省は、提訴後にTikTokが年齢確認や保護者管理機能などの若年ユーザー保護策を大幅に強化したことも和解判断の要因として挙げている。COPPA関連訴訟としては過去最大級の和解金額という。

出典: [ITmedia NEWS](https://www.itmedia.co.jp/news/article/2608/23/2000000701/)

## 個人情報保護委員会、KDDIとISP各社に行政上の対応 メール不正アクセス問題で

個人情報保護委員会は8月19日、KDDIが提供するISP事業者向けメールシステムへの不正アクセス事案について、KDDIおよび関係するインターネットサービスプロバイダ各社に対し個人情報保護法に基づく行政上の対応を行ったと公表した。

法改正・規制動向案件。同事案では最大1223万件のメールアドレスなどが流出したとされる。委員会はKDDI側のアクセス制御などの技術的安全管理措置に不備があったと指摘し、一部ISPではパスワードが暗号化されずに保存されていた点も問題視して改善を求めた。総務省が7月に電気通信事業法上の「通信の秘密」侵害として行政指導を行ったのに続き、今回は個人情報保護の観点から別の当局が対応した形。メールサービス利用者に対しても、同一・類似パスワードの使い回しがあれば速やかに変更するよう注意喚起している。

出典: [個人情報保護委員会](https://www.ppc.go.jp/news/press/2026/260819_01_houdou/)

## CISA、TrueConf Serverの認証不要RCE脆弱性2件をKEVカタログに追加

米CISAは8月20日、社内ビデオ会議・メッセージング基盤「TrueConf Server」の脆弱性2件を悪用が確認された脆弱性（KEV）カタログに追加し、米連邦機関に9月3日までの対応を指示した。

セキュリティインシデント・脆弱性案件（最大3件枠）。追加されたのはTCP 4307ポート経由で認証なしに任意スクリプトを実行できる「CVE-2026-72529」と、サンドボックスを脱出してホストOS上でコマンド実行が可能になる「CVE-2026-72530」で、いずれも深刻度は最高評価。ハクティビスト集団「Head Mare」が7月以降、ロシア・ベラルーシの運輸・エネルギー・IT関連組織を標的にこれらの脆弱性を悪用し、クライアントインストーラーの改ざんなどでバックドアを仕込んでいたことが確認されている。修正版は6月に公開済みで、自社運用しているTrueConf Serverの管理者は速やかな更新が必要。

出典: [BleepingComputer](https://www.bleepingcomputer.com/news/security/cisa-orders-feds-to-patch-actively-exploited-trueconf-server-flaws/)

## ChatGPTの医療助言を巡り、米国の牧師がOpenAIを提訴

米フロリダ州の牧師スコット・ウィンターズ氏が、ChatGPTから受けた医療助言が原因で肺塞栓症を悪化させたとして、OpenAIとCEOサム・アルトマン氏を相手取りカリフォルニア州上級裁判所に提訴した。

## 今日のTips: React 19、`<Context.Provider>`を`<Context>`として直接使えるようになった

React 19以前は、Contextの値を子孫コンポーネントに渡す際、必ず`<Context.Provider>`でラップする必要があった。

```jsx
// 従来（React 18以前）
<ThemeContext.Provider value="dark">
  {children}
</ThemeContext.Provider>

// React 19
<ThemeContext value="dark">
  {children}
</ThemeContext>
```

React 19では`<Context>`自体をプロバイダーとして直接レンダリングできるようになり、`.Provider`の記述が不要になった。公式ブログでは今後`<Context.Provider>`を非推奨化していく方針が示されており、移行を助けるcodemodの提供も予告されている。

<Tip label="▶ 補足">
同時にrefをpropsとして直接受け取れるようになったことで`forwardRef`も非推奨化の方向とされており、`useFormState`も`useActionState`への改名が案内されている。いずれも既存コードが即座に動かなくなるわけではないが、新規実装では新しい書き方への統一を検討する価値がある。
</Tip>
