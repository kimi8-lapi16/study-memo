## Cloudflare、サイトにコード変更なしでWebMCPインターフェースを追加できる機能をプレビュー公開

Cloudflareは、自社サービスを利用するWebサイトに「WebMCP」インターフェースを追加できる新機能を開発者プレビューとして公開した。

新技術紹介案件。ダッシュボードの設定のみで有効化でき、オリジンサーバーやサイトのコード変更は不要。エッジでブリッジスクリプトを注入する方式のため、静的サイト・SPAの両方で動作する。ブラウザ内で動くAIエージェントが、画像のC2PAコンテンツ来歴情報を読み取る「Content Credentials」や、既存のMCPサーバーのツールを呼び出す「Site MCP Server」などをツールとして直接利用できるようになる。処理はブラウザ内で完結し、データはCloudflareには送信されないという。

## Linuxカーネルのロックダウンモード、レガシーI/Oインタフェースが保護対象から漏れるバグが発覚

Linuxカーネルのセキュリティ機構「ロックダウンモード」に、レガシーなI/O・メモリ空間アクセスが保護対象から漏れていたことが分かり、修正パッチが提出された。

開発ツール・言語・OSS動向案件。ロックダウンモードは2019年のLinux 5.4で導入され、root権限があってもカーネルの書き換えを禁止する機構だが、古いPCIデバイス操作用の`legacy_io`・`legacy_mem`インタフェースが見落とされており、root権限を持つユーザーが依然としてI/Oポートへの書き込みを行えた。カーネルメンテナーのKrzysztof Wilczyński氏が提出した修正パッチはLinux 7.3への統合を予定する。デスクトップ用途ではこれらのレガシーインタフェースがほぼ使われないため一般利用への影響は限定的とされるが、30年以上の互換性維持とセキュリティ強化の両立という設計上の難しさを改めて浮き彫りにした。

## 今日のTips: Prismaのインタラクティブトランザクションは既定で5秒（timeout）以内に完了しないと失敗する

`$transaction`にコールバック関数を渡す「インタラクティブトランザクション」には、既定でtimeout（トランザクション全体の実行時間上限）5000ms、maxWait（トランザクションを取得するまでの最大待機時間）2000msが設定されている。外部API呼び出しなど時間のかかる処理をトランザクション内に含めると、既定値を超えた時点でタイムアウトエラーとなりロールバックされる。必要な場合はオプションで個別に延長できる。

```typescript
await prisma.$transaction(
  async (tx) => {
    await tx.order.create({ data: { status: 'pending' } });
    await callExternalApi(); // 遅いと既定5秒でタイムアウトする
  },
  { maxWait: 5000, timeout: 10000 },
);
```

<Tip label="▶ 補足">
timeoutは「トランザクションを開始してから完了するまでの最大実行時間」、maxWaitは「データベース接続（トランザクション）を確保するまでの最大待機時間」を指す、別概念のパラメータ。長時間かかる処理はトランザクションの外に出し、トランザクション内はDB操作だけに留めるのが基本。
</Tip>
