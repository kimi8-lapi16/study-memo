## Microsoft Entra IDに最大深刻度（CVSS10.0）の脆弱性、修正済みも詳細は不明

セキュリティインシデント・脆弱性案件（最大3件枠）。信頼できないデータの逆シリアル化に起因し、認証なしでネットワーク経由の任意コード実行が可能だったという。報道では「実際の攻撃で悪用された」ともされているが、Microsoft自身は「エクスプロイトコードは現時点でオンライン上に出回っていない」とも説明しており、具体的な攻撃事例や被害の詳細は公表されていない。脆弱性はMicrosoft側で既に完全に修正済みで、ユーザー側での対応は不要としている。発見者はMicrosoftのプリンシパルセキュリティエンジニア、Robert Fitzpatrick氏。

## 今日のTips: NestJSのProviderは既定でシングルトン、リクエストごとの状態を持たせると全ユーザーで共有される

NestJSの`@Injectable()`は指定しない限り`Scope.DEFAULT`（シングルトン）になる。アプリ起動時に1つだけインスタンス化され、リクエストをまたいで使い回されるという落とし穴がある。

```ts
@Injectable() // 既定はシングルトン
export class SessionService {
  private currentUserId?: string; // NG: 全リクエストで共有される

  setUser(id: string) {
    this.currentUserId = id; // 別ユーザーのリクエストで上書きされうる
  }
}
```

リクエストごとに独立させたい場合は`Scope.REQUEST`を指定する。ただしリクエストスコープのProviderに依存するControllerやServiceは、依存関係を辿って自動的にリクエストスコープへ「バブルアップ」する。

<Tip label="▶ 補足">
リクエストスコープはリクエストのたびにインスタンスを生成し直すため、平均レスポンスタイムやベンチマーク結果に影響が出るとNestJS公式も明言している。本当にリクエスト単位の状態が必要な場合を除き、既定のシングルトンスコープを使い、状態は引数やメソッドの戻り値でやり取りするのが基本方針とされている。
</Tip>
