## Claude Code、危険コマンドを自動判定する「auto mode」を8月14日から標準化 セッション間メッセージングも追加

Anthropicは、AIコーディングツール「Claude Code」の機能アップデートを相次いで発表した。危険なコマンドの実行可否を分類器が自動判定する「auto mode」が8月14日からPro/Max/Teamプランで既定設定になるほか、複数セッション間でメッセージをやり取りできる新機能も加わった。

AI・LLM動向案件。auto modeは、人間による承認では危険コマンドの検出率が13.6%にとどまるのに対し分類器は89%を検出できたという社内テスト結果を踏まえた変更で、Enterpriseプラン等も1カ月以内に既定化予定。従来ユーザーが実行確認の97%を機械的に承認していた"形骸化した権限確認"の改善が狙いという。あわせて8月7日には、macOS・Linux（WSL 2含む）で複数のClaude Codeセッションが互いにメッセージを送り合える機能も追加され、あるセッションでの変更が別セッションの作業に影響する場合に自律的に通知するといった用途を想定する。

## 中国MiniMax、画像・動画・音楽を参照して一貫性を保てる動画生成AI「MiniMax H3」を公開

中国MiniMaxは、オープンモデルとして動画生成AI「MiniMax H3」を公開した。ローカルPCでも実行可能で、ByteDanceの「Seedance 2.0」に匹敵する性能をうたう。

新技術紹介案件。最大の特徴は「Omni Reference」機能で、画像最大9枚・動画最大3本・音楽最大3本を参照データとして与え、それらとの一貫性を保ちながら動画を生成できる。オープンモデルでこの種の参照機能を備えるのは初めてという。ComfyUI向けの圧縮版も用意されており、RTX 4090搭載PCで1248×832解像度・15秒の動画を約20分で生成できる。

## 今日のTips: NestJSのシャットダウンフックは`enableShutdownHooks()`を呼ばないとSIGTERMで発火しない

`onModuleDestroy` / `beforeApplicationShutdown` / `onApplicationShutdown`は、`app.close()`を明示的に呼ぶか、SIGTERMなどのシステムシグナル受信時に発火するが、後者はブートストラップ時に`enableShutdownHooks()`を呼んで明示的にオプトインしないと機能しない。呼び忘れると、Kubernetesのpod終了やHerokuのdyno停止時にコネクションのクローズ処理などが一切実行されない。

```typescript
async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.enableShutdownHooks(); // これが無いとSIGTERMでonModuleDestroy等が呼ばれない
  await app.listen(3000);
}
```

<Tip label="▶ 補足">
デフォルト無効なのは、shutdown hookのリスナーがシステムリソースを消費するため。Jestの並列テストのように同一Nodeプロセスで複数のNestアプリを起動するケースでリスナー過多の警告が出るのを避ける狙いという。また`SIGTERM`はWindowsではプラットフォームの制約により機能しない（`SIGINT`/`SIGBREAK`は動作する）点にも注意。
</Tip>
