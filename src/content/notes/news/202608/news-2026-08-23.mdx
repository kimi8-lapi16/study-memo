## GitHub、約8時間ダウンの原因は「自動拡張がサイドカーの容量を見ていなかった」こと

GitHubは8月20日、8月17日22時28分〜18日6時15分（世界各地の時刻換算）にかけて発生した約7時間47分の大規模障害について、調査結果を公式ブログで公表した。

クラウド・大規模障害案件。米中部データセンターでサービス間通信を仲介する「Istio」サイドカーが同時処理上限に達したが、自動拡張の仕組みがサイドカーの容量そのものを監視していなかったため増強が働かず、後段の「HAProxy」ロードバランサーも処理上限に達して認証経路の遅延が連鎖した。さらに大量のリトライとGitHub Copilot側の不具合とみられる挙動が重なり、認証リクエストが平常時の毎秒7000〜9000件から7万〜10万件まで急増したという。ピーク時にはWeb機能・APIで約20%、リポジトリダウンロードで約50%のエラーが発生し、Issues・Pull Requests・Actions・Copilot・認証機能に世界的な影響が出た。

## 今日のTips: Prismaの`$use`ミドルウェアはPrisma ORM v7で削除済み、代わりにClient Extensionsを使う

Prismaには以前`prisma.$use()`によるミドルウェアAPIがあったが、Prisma ORM v7へのアップグレードガイドでは、このAPIは既に削除済みで、代わりに`$extends`によるClient Extensionsへの移行が必須と案内されている。

```ts
// 旧: ミドルウェア（v7で削除済み）
prisma.$use(async (params, next) => next(params));

// 新: Client Extensions
const prisma = new PrismaClient().$extends({
  query: {
    user: {
      async findMany({ args, query }) {
        return query(args);
      },
    },
  },
});
```

<Tip label="▶ 補足">
Client Extensionsはモデル・操作単位でクエリをフックする形に変わっており、ミドルウェアのように全モデル横断で1つの関数に処理を集約する書き方はできない。既存の`$use`実装をそのまま移植するのではなく、対象モデル・操作ごとに書き直す前提でアップグレードを計画する必要がある。
</Tip>
