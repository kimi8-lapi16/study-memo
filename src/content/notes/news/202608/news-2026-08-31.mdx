## 今日のTips: Node.jsの`'exit'`イベントリスナーは同期処理しか実行できない

Node.jsの`process`は`'exit'`イベントで終了直前の処理をフックできるが、公式ドキュメントは「リスナー関数は同期処理のみを実行しなければならない」と明記している。

```js
process.on('exit', (code) => {
  setTimeout(() => {
    console.log('This will not run'); // 実行されない
  }, 0);
});
```

`'exit'`イベントの発火直後にNode.jsプロセスは即座に終了するため、イベントループに積まれた`setTimeout`や未解決のPromiseなどの追加処理は破棄される。終了前にDB接続のクローズなど非同期のクリーンアップを行いたい場合は、`'exit'`ではなく`SIGTERM`/`SIGINT`のシグナルハンドラや、イベントループが自然に空になった時点で発火する`'beforeExit'`イベントを使う必要がある。

<Tip label="▶ 補足">
`'beforeExit'`は`process.exit()`の明示呼び出しや未捕捉例外による終了では発火しない。あくまでイベントループが自然に空になったときのみのフックであり、`'exit'`の代替として使うべきではない。
</Tip>
