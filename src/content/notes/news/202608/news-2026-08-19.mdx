## 今日のTips: `sort()`は破壊的、非破壊で使いたいなら`toSorted()`

`Array.prototype.sort()`は元の配列を直接書き換える破壊的メソッドで、呼び出し元と共有している配列を意図せず変更してしまう事故の原因になりやすい。ES2023で追加された`toSorted()`はこの非破壊版で、元の配列を変更せずソート済みの新しい配列を返す。

```js
const months = ['Mar', 'Jan', 'Feb'];
const sorted = months.toSorted();

console.log(sorted); // ['Feb', 'Jan', 'Mar']
console.log(months); // ['Mar', 'Jan', 'Feb'] ← 変更されない
```

同様の非破壊ペアとして、`reverse()`に対する`toReversed()`、`splice()`に対する`toSpliced()`、インデックス指定で1要素だけ置き換えた新しい配列を返す`with()`もある。Reactのstateのようにイミュータブルな更新が前提の場面では、破壊的メソッドより安全な選択になる。

<Tip label="▶ 補足">
比較関数を省略した場合の既定の並び順は、要素を文字列化してUnicodeコードポイント順に比較する点は`sort()`と同じ。数値配列を昇順にしたい場合は`toSorted((a, b) => a - b)`のように比較関数を渡す必要がある。
</Tip>
