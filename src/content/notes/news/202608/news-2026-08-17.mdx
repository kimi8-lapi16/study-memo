## Cloudflare、AI専用の超軽量ヘッドレスブラウザ「Kitesurf」を公開 Chromium比で3〜7倍効率化

Cloudflareは8月17日、AIエージェント専用に設計した超軽量ヘッドレスブラウザ「Kitesurf」をベータ公開した。Rustで実装しWebAssemblyにコンパイルしてCloudflare Workers上で動作し、CPU・メモリ消費でChromiumの3〜7倍の効率を実現するという。

新技術紹介案件。人間向けブラウザに必須のタブ、ブックマーク、拡張機能、テーマ、スムーズスクロールといった機能をAIエージェントには不要と判断し、思い切って削ぎ落とした設計が特徴。Chrome DevTools Protocol（CDP）経由でアクセスできるため、PuppeteerやPlaywrightなど既存の自動化ツールをそのまま使える互換性を保っている。実際に試せるプレイグラウンドがベータ版として公開中。

## 今日のTips: Prismaの`include`はDB側JOINが既定、N+1を避ける「relationLoadStrategy」

Prisma ORMでリレーションを`include`するとき、内部でどうクエリが発行されるか意識したことはあるだろうか。バージョンによっては「関連ごとに個別クエリを投げてアプリ側で結合する」動きをしており、多重クエリの原因になっていた。

`relationLoadStrategy`はこの挙動を選べるオプションで、値は`join`と`query`の2種類。

```prisma
generator client {
  provider        = "prisma-client-js"
  previewFeatures = ["relationJoins"]
}
```

```ts
await prisma.user.findMany({
  relationLoadStrategy: 'join', // 既定
  include: { posts: true },
});
```

`join`はPostgreSQLのLATERAL JOINやMySQLの相関サブクエリを使いDB側でJSON集約して1クエリで返すのに対し、`query`はテーブルごとに複数クエリを送りアプリ側で結合する。現時点で`join`が既定値だが、この機能自体はまだPreview版で`relationJoins`フラグの有効化が必要。対応DBはPostgreSQL・CockroachDB・MySQLのみで、SQLite等では使えない点に注意。

<Tip label="▶ 補足">
アプリケーションサーバーのCPU負荷を抑えたい場合は`join`、DB側の結合コストを避けたい・大きな結果セットを分割して受け取りたい場合は`query`、とクエリの性質で使い分けるのが基本方針とされている。
</Tip>
