## PHP緊急脆弱性「PHP2Shell」、CISAが実際の攻撃での悪用を確認

米CISAは10月26日、PHPの深刻な脆弱性2件(CVE-2026-109618、CVE-2026-109619、通称「PHP2Shell」)を既知の悪用脆弱性(KEV)カタログに追加し、実際の攻撃での悪用を確認したと発表した。

セキュリティインシデント・脆弱性案件(最大3件枠、本日3件目、続報)。両脆弱性は認証不要でリモートコード実行(RCE)が可能な深刻度の高い欠陥で、PHP開発チームが10月21日に修正済み。CISAは連邦政府機関に対し拘束的運用指令26-04に基づき今週木曜までの対処を命じ、全組織にもKEVカタログの優先対応を促した。Cloudflare・Amazon・Hadrian・watchTowr等の複数のセキュリティ企業は、パッチ公開前から広範な悪用試行を検知していたとしており、Amazonの脅威インテリジェンス部門はパッチ公開の4日前から標的化が始まっていたと報告。週末にはApache mod_php上のPHP 8.4.26環境への実際のRCEがハニーポットで観測された。PHPはウェブサイトの約7割で使われ、VirusTotalの推定では510万台超のPHPホストが外部に露出し、うち約380万台は攻撃可能なポートが開いているという。このほか未修正のRCE脆弱性(CVE-2026-115560)も公表されており、PHPが公開した緩和策の適用が推奨される。本件は国内でもさくらインターネットやCygames、pixiv等の緊急メンテナンスを招いた経緯がある。

## 今日のTips: Prismaの`omit`、`select`とは併用できず機密フィールドだけを除外する専用オプション

Prisma Clientには、クエリ結果から特定のフィールドを除外する`omit`オプションがある。公式ドキュメントは「`omit`と`select`は目的が正反対のため併用できない」と明記しており、返すフィールドを絞り込みたいときは`select`、既定の結果をほぼそのまま使いつつパスワードなど機密・不要なフィールドだけ除きたいときは`omit`を使い分けるよう推奨している。

```ts
// クエリ単位で除外
await prisma.user.findUnique({ where: { id }, omit: { password: true } });

// クライアント生成時に既定の除外ルールを設定
const prisma = new PrismaClient({ omit: { user: { password: true } } });
```

`include`でリレーションを取得しつつ、そのリレーション先のフィールドだけを`omit`で除くことも可能。モデル全体のパスワード除外をクライアント単位で固定しておけば、呼び出し側で`select`を毎回書き忘れるリスクを減らせる。

参考: [Prisma Docs: Excluding fields](https://www.prisma.io/docs/orm/prisma-client/queries/excluding-fields)
