## Liquid AI、エッジ向け意思決定モデル「d1」をオープンウェイトで公開

AIモデル企業Liquid AIは10月7日、エッジデバイス上で高速に「意思決定」を返す小型モデル「d1-3B」と実験版「d1-omni-600M」をオープンウェイトで公開した。

AI・LLM動向案件(本日2件目)。d1-3Bはテキストと画像を入力できる本番向けの主力モデルで、同社のLFM2.5-VL-3Bをベースにする。d1-omni-600Mはテキストと画像、またはテキストと音声を扱える実験的な最初のチェックポイントで、双方向エンコーダのLFM2.5-Encoder-350Mがベース。いずれもHugging Faceで無制限にダウンロード・ファインチューニング・デプロイできるとしている。独自ベンチマーク「Decision Index v0.2.1」ではd1-3Bが48.57を記録し、同社によれば10B未満の全モデルを上回り、12倍の大きさの35Bモデルに匹敵するという。推論速度はd1-3Bの1クエリあたりでNVIDIA RTX 4090が8ms、Jetson Orin Nanoでも50ms程度としており、ジェスチャー操作のゲームやコンテンツモデレーションへの応用例を挙げている。10月5日に公開したAPI版「d1」に続く、オープンウェイト版の提供となる。

## GitHub、プルリクエストのアーカイブ権限をTriage役にも拡大

## 今日のTips: Node.jsの`process.loadEnvFile()`、既に設定済みの環境変数は上書きしない

Node.js v20.12/v21.7で追加された`process.loadEnvFile(path)`は`.env`ファイルを`process.env`に読み込む組み込みAPIで、v22.21/v24.10で実験的機能のステータスが外れた。`dotenv`パッケージを入れなくても、簡単な`.env`読み込みはこれ1行で済む。

```js
import { loadEnvFile } from 'node:process';

loadEnvFile(); // 既定で './.env' を読み込む
console.log(process.env.FOO);
```

<Note>
シェルなどで既に`FOO`が設定されている場合、`.env`側の値では上書きされない。実際に`FOO=from_shell`を設定した状態で`.env`に`FOO=from_file`と書いて試すと、`process.env.FOO`は`"from_shell"`のままだった(デプロイ環境の環境変数を`.env`で誤って覆ってしまう事故を防げる)。
</Note>

参考: [Node.js Docs — process.loadEnvFile(path)](https://nodejs.org/api/process.html#processloadenvfilepath)
