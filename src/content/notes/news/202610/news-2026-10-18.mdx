## Eストアー(BASEグループ)、不正アクセスで最大約2335万人分の情報流出 カード情報の一部も対象

ECサイト構築サービス「ショップサーブ」を運営するEストアー(BASEの完全子会社)は10月16日、不正アクセスにより最大約2335万人分の情報が流出した可能性があるとする最終報告を公表した。

セキュリティインシデント案件(最大3件枠)。攻撃者はサーバー上のアプリケーションの脆弱性を突いて不正プログラムを実行し、5月21日から8月1日の間にデータベースの内容を外部送信していた。対象はショップサーブの現行・過去利用店舗7858店と、その購入者・会員など。店舗側は管理画面のログインID・パスワードや代金引換の店舗情報、ショッパー側は氏名・住所・電話番号・メールアドレス・勤務先情報・暗号化パスワードなどで、うち約209万人分はカード会員名・カード番号の先頭6桁と末尾4桁・有効期限も含まれる。完全なカード番号やセキュリティコードは保有していないため、流出情報だけでは決済に利用できないとしている。8月1日の検知時点で通信を遮断済みで、10月16日時点で二次被害やダークウェブへの投稿は確認されていない。

出典: [ITmedia NEWS](https://www.itmedia.co.jp/news/article/2610/17/2000002349/)

## ConnectWise Cloud Backupの認証情報窃取を起点に、Microsoft 365テナントへの不正アクセスが拡大

ConnectWiseは、同社のクラウドバックアップサービス「Cloud Backup」(旧SkyKick Cloud Backup)でアプリケーションIDへの不正アクセスを確認したと発表し、これを起点にMicrosoft 365テナントが侵害される事例が相次いでいる。

セキュリティインシデント案件(最大3件枠、本日2件目)。攻撃者はユーザーのサインインを介さず、Cloud Backupアプリ自体としてシークレットを使い自動化スクリプトでM365に直接認証したため、MFAでは防げなかった。アプリに付与済みの権限によりメール・OneDrive/SharePoint・Teamsチャットへアクセスでき、一部テナントではサービスプリンシパルが自身にExchange管理者ロールなどを付与、あるテナントではCloud ManagementアプリがGlobal Administrator権限を自身に付与して他アプリの認証情報を追加する事例もあった。セキュリティ企業Huntressは少なくとも162テナントの侵害を確認しており、攻撃活動は少なくとも10月15日から単一IPアドレスから行われていたという。ConnectWiseは顧客のCloud Backupへのアクセスを停止して調査中で復旧時期は未定、バックアップデータの持ち出しは確認されていないとしている。管理者には対象アプリの無効化と、10月13日以降に追加されたシークレット・証明書の確認が推奨されている。

## Linuxカーネルに「PwnEscape」、ゲストVMからホストでコード実行の脆弱性 クラウド各社が対応開始

Linuxカーネルのネットワーク処理に、仮想マシンのゲストからホストOS側で任意コード実行につながる重大な脆弱性「PwnEscape」(CVE-2026-99999、CVSS 9.3)が公表された。

セキュリティインシデント案件(最大3件枠、本日3件目)。Openwallのoss-securityメーリングリストに10月15日付で投稿された研究によると、検証済みのIPv4ヘッダのチェックサム関連データを書き換えることで検証済みヘッダ自体を上書きでき、結果として任意のメモリ読み書きが可能になる。研究チームはKVM環境でホストOS上のコード実行まで確認しており、投稿のタイトルはKVMからのゲスト・ホスト間脱出を指すが、コンテナなど他環境でも同様の攻撃が成立する可能性があるとしている。投稿は、設定が弱い環境向けの実用的な悪用コードが数週間以内に、既定設定のハイパーバイザー向けも1カ月程度で出回ると予測。さくらインターネットはVPSやレンタルサーバーなど一部サービスの新規申し込みを停止して対応中で、AWSはEC2・Lambda・Fargateなどのマネージドサービスは影響を受けず利用者側の対応は不要と説明している。

## 今日のTips: Node.jsのネイティブTypeScript実行、`enum`やデコレータは構文エラーになる

Node.js(v23.6.0/v22.18.0以降はデフォルト有効)は`.ts`ファイルをトランスパイルなしで直接実行できるが、これは型注釈を空白に置き換える「型の消去」だけで、型チェックは一切行われない。さらに`enum`宣言、値を持つ`namespace`、パラメータプロパティ、インポートエイリアスのように新しいJS構文への変換が必要な機能はサポート外で実行時エラーになる。TC39 Stage 3段階のデコレータも変換されず、パースエラーになる。

<Note>
`tsconfig.json`も読み込まれないため、`paths`によるエイリアス解決やダウンレベリングは効かない(`#`始まりのsubpath importsが代替)。`type`を付けない型専用importはランタイムimportとして実行時エラーになる点にも注意。`tsconfig.json`やenum変換まで含めて動かしたい場合は、公式ドキュメントも`tsx`などのサードパーティツールの利用を案に挙げている。
</Note>

```ts
enum Color { Red, Blue } // ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX で実行時エラー
namespace A { export let x = 1 } // 値を持つnamespaceも同様にエラー
namespace B { export type T = string } // 型のみのnamespaceはOK
```

参考: [Node.js Docs — Type Stripping](https://nodejs.org/api/typescript.html)
