## 今日のTips: TypeScriptのnarrowing、クロージャ内でも効くが"どこかで"再代入があると失われる

`typeof`チェックなどで絞り込んだ変数は、素直に読めばクロージャ(コールバック)の中では使えなさそうに見える。実際はconstや書き換えのないパラメータなら、クロージャ内でも絞り込みが保持される。ただし関数内の"どこかで"その変数への再代入があると、クロージャ内の絞り込みは失われる。再代入が絞り込みより後の行にあっても結果は同じ。

```ts
function f(x: string | undefined) {
  if (typeof x !== 'string') return;
  setTimeout(() => x.toUpperCase()); // OK: xは再代入されない
}
function g(x: string | undefined) {
  if (typeof x !== 'string') return;
  setTimeout(() => x.toUpperCase()); // Error: 'x' is possibly 'undefined'
  x = undefined; // この再代入の存在だけでクロージャ内の絞り込みが無効化される
}
```

<Tip>
クロージャはいつ実行されるか分からないため、TypeScriptは「その変数が関数内のどこかで再代入され得るか」だけを見て絞り込みを諦める。再代入される側だけ安全側に倒ってほしい場合は、絞り込み直後に`const`の別名(`const y = x`)へ移してからクロージャで使うと回避できる。
</Tip>
