## Deno開発元がCloudflareに合流、Denoの開発は1年後に終了へ

JavaScript/TypeScriptランタイム「Deno」の開発元Deno Landが、Cloudflareに合流すると発表した。

開発ツール・言語・OSS動向案件。Denoは、Node.jsの作者であるRyan Dahl氏がNode.jsの設計上の後悔を踏まえて開発したランタイムで、Deno Landはエッジ実行環境「Deno Deploy」やパッケージレジストリ「JSR」も運営していた。Deno Landは8月、Cloudflare Durable Objects互換のオープンソース実装「celld」を公開しており、インフラロックインを避けつつ分散アプリを構築できる狙いがあった。今回の合流は単純な買収・救済ではなく両社の技術的方向性が一致した結果だとされ、Dahl氏とBert Belder氏はCloudflare Workersのオープンソース実装「workerd」をセルフホスト対応の正式サポート対象にする取り組みを主導する。Denoの開発自体は、今後1年間バグ修正とセキュリティアップデートのみ提供した後に終了する予定(ソースはオープンソースのまま残るため他の開発者が引き継ぐ可能性はある)。Deno Deployは6カ月後に終了し、Cloudflare Workersへの移行サービスが提供される。JSRはインフラをCloudflareに移行し継続する。

## ノルウェー当局、MicrosoftのXandrにGrindrデータ共有で過去最高額の制裁金

ノルウェーのデータ保護当局Datatilsynetは、Microsoft傘下の広告企業Xandr(現Microsoft Advertising)に対し、出会い系アプリ「Grindr」利用者の機微なデータを違法に処理・共有したとして、同国として過去最高額となるNOK9200万(約9.6百万ドル)の制裁金を科した。

法改正・規制動向案件。2018年7月から2020年4月にかけて、XandrはGrindr内のリアルタイム広告オークションを運営し、広告主はXandrから渡されたプロファイリング情報をもとに利用者への広告表示権を競っていた。この過程で性的指向に関する情報を含む利用者データが数千の企業に露出した可能性があるという。XandrはGrindrと共同管理者の立場にあり明示的な同意を検証する責任があったが、Grindrが有効な同意を得ていると想定したまま検証を行わなかったと判断された。2020年1月にオーストリアの非営利団体noybとノルウェー消費者評議会が申立てを行い、今回の決定に至った。Xandrには3週間の上訴期間が与えられ、Microsoftは調査対象が自社によるXandr買収前の行為だとしつつ、決定を検討し「選択肢を評価している」とコメントしている。

## GitLab、CI/CDの正規表現コンパイラに最高深刻度のRCE脆弱性

GitLabは、CI/CDの正規表現コンパイラに存在する最高深刻度(Critical)の脆弱性CVE-2026-97229を修正した。

セキュリティインシデント案件(最大3件枠、本日3件目)。原因は正規表現検証の不備による整数オーバーフロー(CWE-190)で、特定の条件下では未認証の攻撃者がCI/CD設定ファイルに細工した正規表現を仕込むことで、GitLabサーバー上で任意のコードを実行できる可能性がある。HackerOne経由で研究者「joaxcar」が報告した。対象はセルフマネージド環境のGitLab CE/EEで、19.2系は19.2.8未満、19.3系は19.3.4未満、19.4系は19.4.2未満。GitLab.comは既にパッチ適用済み、GitLab Dedicatedの顧客は対応不要としている。GitLabでは1月にも2要素認証を回避できる高深刻度脆弱性、9月にも実際に悪用偵察を受けた最高深刻度のパストラバーサル脆弱性が見つかっており、セルフホスト利用者には早急なアップグレードが呼びかけられている。

## 今日のTips: TypeScript 5.0以降、デコレータの既定はTC39標準になりNestJSのDIに影響する

TypeScriptは5.0から、デコレータ構文としてTC39 Stage 3の標準仕様をサポートした。これは`experimentalDecorators`を明示的に有効にしない限り使われる既定の挙動であり、NestJSが依存する従来の(experimental/legacy)デコレータとは別物になる。

```jsonc
// NestJSのtsconfig.jsonで必須
{
  "compilerOptions": {
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true
  }
}
```

<Note>
`emitDecoratorMetadata`は`experimentalDecorators`時代のデコレータでのみ機能する機能で、有効にすると`reflect-metadata`経由でプロパティ/パラメータの型(`design:type`)を実行時に取得できるようになる。NestJSのコンストラクタインジェクションはこの`design:type`を読んでDIを解決しているため、TC39標準デコレータに切り替えると型情報が得られずDIが壊れる。実際にNestJS公式のtypescript-starterのtsconfig.jsonでも、この2つは明示的に`true`に設定されている。
</Note>

参考: [TypeScript Handbook — Decorators](https://www.typescriptlang.org/docs/handbook/decorators.html), [nestjs/typescript-starter — tsconfig.json](https://github.com/nestjs/typescript-starter/blob/master/tsconfig.json)
