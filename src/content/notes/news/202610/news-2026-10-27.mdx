## 今日のTips: NestJSの終了フック、`onModuleDestroy`→`beforeApplicationShutdown`→`onApplicationShutdown`は初期化と逆順に実行される

NestJSの終了処理は、モジュール初期化(`onModuleInit`→`onApplicationBootstrap`)とは逆順で実行される。

公式ドキュメントによれば、初期化フックはモジュール単位で呼ばれ、依存関係の末端からルートモジュールへ(ルートモジュールが最後)という順で実行される。これに対し終了フックは`onModuleDestroy()`→`beforeApplicationShutdown()`→`onApplicationShutdown()`の順で呼ばれ、公式ドキュメントは "the shutdown hooks run in the reverse order"(初期化とは逆順)と明記している。`beforeApplicationShutdown()`は全モジュールの`onModuleDestroy()`完了後に呼ばれ、`onApplicationShutdown()`は`app.close()`の最終ステップとして実行される。

```ts
class UsersModule {
  onModuleInit() {}    // 初期化: 先に呼ばれる(リーフ側)
  onModuleDestroy() {} // 終了: 後に呼ばれる
}
class AppModule {
  onModuleInit() {}    // 初期化: 最後に呼ばれる(ルート)
  onModuleDestroy() {} // 終了: 先に呼ばれる
}
```

<Note>
終了フックはデフォルトでは発火しない。`app.close()`を明示的に呼ぶか、`app.enableShutdownHooks()`でSIGTERM等のシグナルを有効化する必要がある。
</Note>
