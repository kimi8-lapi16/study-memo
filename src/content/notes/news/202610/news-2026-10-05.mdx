## Supabase、SQLiteデータベース企業Tursoを買収 エージェントAI時代の大量DB需要に対応

Supabaseは10月2日、SQLiteをベースにしたクラウドデータベースサービスを提供するTursoを買収すると発表した。

業界動向案件。Supabaseは既存ユーザーに影響はないとし、買収後もSupabaseはPostgres、TursoはSQLiteの開発をそれぞれ継続する。TursoはSQLiteをフォークした「libSQL」をベースに、1台のサーバで数百万のデータベースをホストし、必要に応じて起動・未使用時は一時停止できるアーキテクチャを持つ。背景には、AIエージェントによるプロトタイピングやダッシュボード生成が広がり、週100万件超のペースでデータベースが新規作成される中、本番向けのPostgresだけでは需要を支えきれなくなってきたという事情がある。買収額は非公開。

## 今日のTips: Reactの`useOptimistic`、失敗時のロールバックは自動だがエラー表示は自前で書く必要がある

React 19の`useOptimistic`は、非同期アクションの結果を待たずに楽観的なUIを即時表示できるフック。アクションが失敗した場合、ロールバック自体は自動で行われる一方、ユーザーへのエラー表示は呼び出し側でハンドリングする必要がある。

```js
const [optimisticItems, removeItem] = useOptimistic(
  items,
  (current, idToRemove) => current.filter((i) => i.id !== idToRemove),
);

function handleDelete(id) {
  startTransition(async () => {
    removeItem(id); // 即時に楽観的な表示へ
    try {
      await deleteAction(id);
    } catch (e) {
      setError(e.message); // 表示はこちらで明示的に出す
    }
  });
}
```

<Tip>
公式ドキュメントによれば、アクションがエラーを投げるとTransitionは終了し、Reactは現在の(楽観的更新前の)`value`で再レンダリングする。親は通常成功時にのみ`value`を更新するため、失敗時は`value`が変わらず画面は更新前の状態に戻る。つまりロールバックのコードを自分で書く必要はないが、「失敗した」というフィードバックをユーザーに見せたい場合はcatchブロックで明示的にエラー状態を扱わないと、画面は何も起きなかったかのように元へ戻るだけになる。
</Tip>
