## MicrosoftのClaude Code・Copilot CLI導入分析、生産性は周囲の利用状況に左右

Microsoftは、社内のソフトウェアエンジニアを対象にコマンドラインで動くAIコーディングツール「Claude Code」「Copilot CLI」の導入実態を分析した調査結果を明らかにした。

AI・LLM動向案件。2026年1月5日から4月29日までの約4カ月間、マージ済みプルリクエスト数を生産性の指標として調査した。導入のきっかけは周囲の利用状況に強く左右され、上司の上司を共有する同僚の4分の1以上が直近2週間で使っていた場合、試用のオッズは最大216%上昇、直属の上司が使っている場合は82%、コードレビューの相手が使っている場合は54%それぞれ上昇した。普段からコードを多く書く人ほど定着しやすく、逆に以前から別のAIツールを使っていた人は試すものの定着しにくい傾向があった。導入初週に利用したエンジニアは、未導入の場合と比べマージ済みプルリクエストが平均24%増加し、この効果は4カ月間安定して続いた。ツール別ではClaude Code利用者が約11.4%、Copilot CLI利用者が約24.9%の向上。本調査は相関を示す観察研究であり、因果関係を断定するものではないとしている。

## うるう秒、2027年5月に廃止決定 国際度量衡総会が採択

フランス・ベルサイユで開催された国際度量衡総会は10月15日(現地時間)、「うるう秒」を2027年5月20日に廃止する決議を採択した。

法改正・規制動向案件。うるう秒は協定世界時と地球の自転のずれを補うため6月末か12月末に1秒を加える仕組みで、1972年の導入以来27回実施されてきた。同じ時刻が重複することでコンピュータの誤作動やシステム停止を招く恐れがあり、2012年には国内ISPでサーバー障害、オーストラリアでは航空機の搭乗手続きに支障が出て多数便が遅延した事例がある。廃止により時刻のずれの許容範囲は0.9秒から1時間に広がり、数世紀は調整が不要になる見通しで、通信・金融取引システムの安定化が期待される。2022年の前回総会では2035年までの廃止が決まっていたが、今回その時期が前倒しされた。「秒」自体を光格子時計などで再定義する作業も続いており、2030年の次回総会で新定義と実施時期を提案する予定という。

## 今日のTips: Reactのエラーバウンダリ、イベントハンドラ内のエラーはキャッチしない

Reactのエラーバウンダリ(`componentDidCatch`/`static getDerivedStateFromError`を実装したクラスコンポーネント)がキャッチするのは、レンダリング中に子コンポーネントが投げたエラーだけ。クリックハンドラなどのイベントハンドラ内で投げたエラーは対象外で、キャッチされずにそのまま伝播する。

<Note>
公式ドキュメントは、エラーバウンダリがキャッチしないケースとして「イベントハンドラ」「サーバーサイドレンダリング」「エラーバウンダリ自身が投げたエラー(子コンポーネントのエラーではない)」「`setTimeout`や`requestAnimationFrame`などの非同期コード」の4つを明記している。ただし非同期コードには例外があり、`useTransition`が返す`startTransition`関数内で投げたエラーはエラーバウンダリでキャッチされる。イベントハンドラのエラーを画面に出したい場合は、`try/catch`で捕捉して`useState`等に保持し、通常のレンダリングでエラー表示を行う必要がある。
</Note>

```tsx
function Button() {
  const handleClick = () => {
    throw new Error('イベントハンドラのエラー'); // ErrorBoundaryはキャッチしない
  };
  return <button onClick={handleClick}>Click</button>;
}
```

参考: [React Docs — Catching rendering errors with an Error Boundary](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary)
