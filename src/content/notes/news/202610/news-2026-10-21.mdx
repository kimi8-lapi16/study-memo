## 今日のTips: NestJSのDIスコープ、REQUESTスコープは依存チェーンを遡って上位のクラスまで伝播する

あるプロバイダーを`Scope.REQUEST`にすると、そのプロバイダーに依存するコントローラーやサービスも自動的にREQUESTスコープになる。開発者が個別に指定しなくても、依存の連鎖をたどって決まる仕組みで、公式ドキュメントは「リクエストスコープのプロバイダーに依存するコントローラーは、それ自身もリクエストスコープになる」と説明している。

```ts
@Injectable({ scope: Scope.REQUEST })
export class CatsService {}

@Controller('cats')
export class CatsController {
  constructor(private catsService: CatsService) {}
  // CatsServiceに依存しているため、CatsControllerも暗黙にREQUESTスコープになる
}
```

<Note>
伝播するのはREQUESTスコープのみで、`Scope.TRANSIENT`は伝播しない。シングルトンのサービスがTRANSIENTのロガーを注入しても、そのサービス自体はシングルトンのまま。REQUESTスコープは依存チェーン上のクラスをリクエストごとに再生成するため、意図せず広範囲に波及させるとパフォーマンスに影響する。
</Note>

参考: [NestJS Documentation — Injection scopes](https://docs.nestjs.com/fundamentals/injection-scopes)
