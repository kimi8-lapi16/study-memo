## Anthropic、Claude CodeをTypeScriptで拡張できる「Mods」を正式リリース

Anthropicは10月1日、Claude CodeをTypeScriptのコードでカスタマイズできる新機能「Mods」を正式リリースした。

開発ツール・言語・OSS動向案件。従来のHooksがシェルコマンド実行に限られていたのに対し、Modsはセッション内で状態を保持するTypeScript関数を登録でき、プロンプトの書き換えやUIコンポーネント(ボタン・入力フォーム・ペインなど)の追加・変更、ツール呼び出しのブロック・再試行、権限要求の自動承認/拒否といった挙動まで変更できる。プラグインとして配布され、Claude Code 2.1.287以降ではCLI・デスクトップアプリの両方でデフォルト有効になっている。

出典: [gihyo.jp](https://gihyo.jp/article/2026/10/claude-code-mods)

GitLabは10月2日、セルフホスト型のAI Gatewayに存在するCVSS 9.9の重大な脆弱性(CVE-2026-90970)を修正した。

## 今日のTips: NestJSのREQUESTスコープ、使うとコントローラーまで丸ごとリクエストスコープ化する

NestJSのプロバイダーには`DEFAULT`(シングルトン)・`REQUEST`・`TRANSIENT`の3種類のスコープがあるが、`REQUEST`スコープは依存関係の鎖全体に波及する。あるプロバイダーを`REQUEST`スコープにすると、それに依存するコントローラーなど上位のコンポーネントも自動的に`REQUEST`スコープになってしまう。

```ts
// CatsController ← CatsService ← CatsRepository の依存関係で
// CatsService だけを REQUEST スコープにしても…
@Injectable({ scope: Scope.REQUEST })
export class CatsService {}
// → CatsController も連鎖的に REQUEST スコープになる
```

<Tip>
`TRANSIENT`はこの連鎖ルールに従わない。シングルトンのサービスが`TRANSIENT`プロバイダーを注入しても、シングルトン自体はリクエストスコープ化されず、注入されたインスタンスだけがリクエストごとに新規生成される。`REQUEST`スコープはリクエストごとにインスタンスを再生成するためDIのキャッシュが効かずパフォーマンスに影響するほか、WebSocket Gatewayやパスポート戦略など単一インスタンスであるべきプロバイダーには使えない点にも注意。
</Tip>
