## 今日のTips: PostgreSQLのMERGE文、1つの対象行が複数のソース行とマッチすると「カーディナリティ違反」エラーになる

PostgreSQL 15で追加されたSQL標準の`MERGE`文は、`INSERT`・`UPDATE`・`DELETE`を`WHEN`句の条件分岐で1文にまとめられ、`INSERT ... ON CONFLICT`より表現力が高い。だが、結合条件の書き方を誤ると`ON CONFLICT`には無い落とし穴にはまる。

```sql
MERGE INTO customer_account ca
USING recent_transactions t
ON t.customer_id = ca.customer_id
WHEN MATCHED THEN
  UPDATE SET balance = balance + transaction_value
WHEN NOT MATCHED THEN
  INSERT (customer_id, balance)
  VALUES (t.customer_id, t.transaction_value);
```

<Note>
`USING`側(ソース)に同じキーの行が複数あり、対象(ターゲット)の1行と複数回マッチしてしまうと、2回目以降の`UPDATE`/`DELETE`は「cardinality violation」エラーで失敗する(`INSERT`なら一意制約違反になる)。これはSQL標準で要求される挙動で、同じ行への2回目以降の更新を黙って無視する従来の`UPDATE ... FROM`/`DELETE ... USING`とは異なる。`MERGE`を使う際は、結合条件がターゲット行に対してソース行を一意に絞り込めているかを事前に確認する必要がある。
</Note>

参考: [PostgreSQL Documentation — MERGE](https://www.postgresql.org/docs/current/sql-merge.html), [PostgreSQL 15 Release Notes](https://www.postgresql.org/docs/15/release-15.html)
