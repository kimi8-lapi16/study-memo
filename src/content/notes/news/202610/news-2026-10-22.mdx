## Cloudflare、TypeScriptをRustで書き直した高速コンパイラ「tsrs」を発表

## 今日のTips: Prismaの`createMany()`、戻り値は件数のみでネストしたリレーション書き込みにも非対応

`createMany()`は複数レコードをトランザクション内で一括作成できるが、戻り値は`BatchPayload`型(`{ count: 3 }`のような件数のみ)で、作成されたレコード自体は返ってこない。トップレベルの`createMany()`ではネストした`create`/`createMany`/`connect`/`connectOrCreate`も使えず、リレーションの同時作成・接続はできない。

```ts
const result = await prisma.user.createMany({
  data: [{ email: 'a@example.com' }, { email: 'b@example.com' }],
  skipDuplicates: true,
});
// result は { count: 2 } のみ。作成したレコード本体は取得できない
```

<Note>
重複をスキップする`skipDuplicates`オプションは`ON CONFLICT DO NOTHING`に相当する処理に対応したデータベースでのみ使え、公式リファレンスの対応表ではMongoDBとSQL Serverが対象外とされている。作成したレコードが必要な場合や、作成と同時にリレーションも張りたい場合は、`update()`/`create()`内のネストした`createMany`を使うか、個々の`create()`をループで呼ぶ必要がある。
</Note>

参考: [Prisma Client API reference — createMany()](https://www.prisma.io/docs/orm/reference/prisma-client-reference#createmany)
