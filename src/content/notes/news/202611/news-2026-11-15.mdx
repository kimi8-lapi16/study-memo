## AIコードエディタ「Cursor」にサプライチェーン侵害、改ざん版Claude Code拡張が11時間配布される

AIコードエディタ「Cursor」の開発元は、AI基盤プロバイダ「Fireworks AI」から窃取された認証情報を起点に、拡張機能マーケットプレイスへ改ざん版のClaude Code拡張機能が配置されていたと公式に認めた。

セキュリティインシデント・脆弱性案件(最大3件枠、本日1件目)。攻撃者はFireworks AI上のアクセスキーを入手し、CursorがFireworksとの情報共有に使っていた読み取り専用ストレージバケットからデータを窃取。バケット内にはPrivacy Mode未使用ユーザーのAIコーディングエージェントのトレースが含まれ、一部に残っていた暗号化されていないAPI認証情報からCursorの他システムへ侵入されたとみられる。悪意ある拡張機能(バージョン2.1.312/2.1.313)は10月29日に公開され約11時間利用可能な状態にあり、PCに永続的なSSHバックドアを仕込むJavaScriptが含まれていた。影響を受けたのはコーディングエージェントのトレース流出がユーザーの0.05%未満、API認証情報の侵害が顧客の0.01%未満で、本番インフラや顧客のコードリポジトリ自体は影響を受けていないという。研究者によれば、コーディングミスによりSSHが未有効化の多くのWindows/macOS環境では正常動作しなかったとみられる。CursorはFireworksのアクセスキー無効化、認証情報のローテーション、マーケットプレイスの再構築などを実施した。この件はAI開発者向けプラットフォームを狙う攻撃の波の一部とされ、Railway・OpenCode・Northflank・Lightning AI・Warpなども同種の被害を受けている。

## 今日のTips: Prismaの`upsert`、同時実行時はユニーク制約エラーが起きる可能性があり「完全にアトミック」ではない

Prisma Clientの`upsert`は、対象レコードの有無を確認してから作成または更新する処理のため、2つ以上の`upsert`が同時に実行され対象レコードがまだ存在しない場合、競合状態(race condition)が発生し得る。公式リファレンスも「If two or more upsert operations happen at the same time and the record doesn't already exist, then a race condition might happen」と明記しており、一方の`upsert`が稀にユニークキー制約エラー(`P2002`)を投げる可能性がある。

```ts
try {
  await prisma.user.upsert({
    where: { email },
    update: {},
    create: { email },
  });
} catch (e) {
  if (e.code === 'P2002') {
    // 競合時は再試行してupdateに倒す
  }
}
```

<Note>データベース側がネイティブな`INSERT ... ON CONFLICT`としてupsertを実行できる場合(PostgreSQL/CockroachDB/SQLiteなど一部条件)はこの種のユニーク制約エラーは発生しないが、Prisma Client側で存在確認→作成/更新の2段階になるケースでは起こり得るため、`P2002`を捕捉して再試行する実装にしておくと安全。</Note>

参考: [Prisma Client Reference — upsert()](https://www.prisma.io/docs/orm/reference/prisma-client-reference#upsert)
