## 今日のTips: PostgreSQLの`CREATE INDEX CONCURRENTLY`、失敗すると`INVALID`な索引が残り続ける

PostgreSQLの`CREATE INDEX CONCURRENTLY`は、通常の`CREATE INDEX`が書き込み(INSERT/UPDATE/DELETE)をブロックしてテーブルをロックするのに対し、書き込みを止めずにインデックスを作成できる。本番環境の大きなテーブルに後からインデックスを追加する際に使われる手法。

ただし内部的には2回のテーブルスキャンと複数のトランザクションに分けて実行され、デッドロックや一意制約違反などで途中失敗すると、カタログに`INVALID`な索引だけが残ってしまう。無効な索引はクエリでは使われないが、書き込み時の更新コストはそのままかかり続ける。

```sql
-- INVALID な索引を確認(psqlの\dでも INVALID と表示される)
SELECT indexrelid::regclass FROM pg_index WHERE NOT indisvalid;

-- 削除して作り直す、または REINDEX で直す
DROP INDEX idx;
CREATE INDEX CONCURRENTLY idx ON tab (col);
-- もしくは
REINDEX INDEX CONCURRENTLY idx;
```

<Note>`CREATE INDEX CONCURRENTLY`はトランザクションブロック内では実行できず、パーティションテーブルには直接使えない(各パーティションに個別に作成してから親の索引を非concurrentで作る必要がある)。</Note>

参考: [PostgreSQL Documentation — CREATE INDEX](https://www.postgresql.org/docs/current/sql-createindex.html)
