## 今日のTips: Prismaの`$queryRawUnsafe`、位置パラメータを使えば`$queryRaw`と同じくエスケープされる

Prismaの`$queryRaw`はタグ付きテンプレートリテラルからプリペアドステートメントを生成し、変数を自動的にエスケープするためSQLインジェクションから安全とされる。一方`$queryRawUnsafe`はSQL文字列を直接渡せる分柔軟だが、ユーザー入力をそのまま文字列結合すると注入の余地が生まれて危険になる。ただし`$queryRawUnsafe`でも`$1`のような位置パラメータに値を渡す形であれば、タグ付きテンプレートと同様に変数はエスケープされる。

```ts
// 安全: タグ付きテンプレートでプリペアドステートメント化
await prisma.$queryRaw`SELECT * FROM users WHERE id = ${userId}`

// 危険: 文字列結合でUnsafeに渡すと注入の余地がある
await prisma.$queryRawUnsafe(`SELECT * FROM users WHERE id = ${userId}`)

// Unsafeでも位置パラメータなら変数はエスケープされる
await prisma.$queryRawUnsafe('SELECT * FROM users WHERE id = $1', userId)
```

<Note>`$executeRawUnsafe`も同様の注意が必要で、Prisma公式ドキュメントは可能な限り`$executeRaw`を使うよう勧めている。</Note>

参考: [Raw queries | Prisma ORM Docs](https://www.prisma.io/docs/orm/prisma-client/using-raw-sql/raw-queries)
