## 今日のTips: Reactの`useId`、リストの`key`や`use()`のキャッシュキーには使ってはいけない

`useId`はアクセシビリティ属性(`aria-describedby`や`htmlFor`と`id`の組み合わせなど)に渡す一意なIDを生成するためのフックで、同じコンポーネントがツリー内で何度描画されてもID同士が衝突しない。

```jsx
function PasswordField() {
  const passwordHintId = useId();
  return (
    <>
      <input type="password" aria-describedby={passwordHintId} />
      <p id={passwordHintId}>18文字以上で入力してください</p>
    </>
  );
}
```

<Tip>公式ドキュメントは、`useId`が生成する値を「リストの`key`」や「`use()`のキャッシュキー」には使うべきではないと明記している。値はコンポーネントのマウント中は安定するがレンダリング中に変わる可能性があり、そもそもデータの各項目に紐づいた値ではないため。keyやキャッシュキーにはデータ由来のID(例: `item.id`)を使う必要がある。なお`useId`はコンポーネントの「親からのパス」を基に値を生成する仕組みのおかげでサーバーとクライアントのID不一致によるハイドレーションエラーを避けられるが、同じページに複数のReactアプリを置く場合は`createRoot`/`hydrateRoot`の`identifierPrefix`をサーバー・クライアント間で一致させる必要がある。</Tip>
