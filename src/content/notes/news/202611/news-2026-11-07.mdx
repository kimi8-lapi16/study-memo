## 今日のTips: PostgreSQLのCHECK制約・外部キー、`NOT VALID`で追加すれば大テーブルでも書き込みを止めない

既存行を検証せず制約だけを追加する`NOT VALID`オプションを使うと、大きなテーブルへのCHECK制約・外部キー制約の追加を、書き込みをブロックせずに行える。

通常の`ALTER TABLE ... ADD CONSTRAINT`は、既存の全行が制約を満たすか確認するためにテーブルをスキャンし、完了するまで`ACCESS EXCLUSIVE`ロックで他の更新をブロックし続ける。大きなテーブルではこのスキャンが長時間かかり、本番環境への影響が大きい。

```sql
-- 1. スキャンを省略して制約だけ追加(ACCESS EXCLUSIVEの保持は短時間)
ALTER TABLE orders ADD CONSTRAINT orders_amount_check
  CHECK (amount >= 0) NOT VALID;

-- 2. 別トランザクションで既存行を検証
ALTER TABLE orders VALIDATE CONSTRAINT orders_amount_check;
```

`NOT VALID`で追加した制約は、以後のINSERT/UPDATEには即座に適用される。既存行の検証は`VALIDATE CONSTRAINT`で別途行い、こちらは`SHARE UPDATE EXCLUSIVE`ロックしか取得しないため、他のトランザクションからの読み書きをブロックしない。外部キー制約の場合は`ADD FOREIGN KEY`自体がもともと`SHARE ROW EXCLUSIVE`ロックで済むため、`NOT VALID`の効果はスキャンを伴う`ACCESS EXCLUSIVE`ロックが発生するCHECK制約で特に大きい。

<Tip>すでに制約違反の行があるとわかっているテーブルでも、`NOT VALID`で先に制約を効かせて新規の違反行を防ぎ、既存の違反行は後から順次修正して`VALIDATE CONSTRAINT`を通す、という段階的な移行に使える。</Tip>

参考: [ALTER TABLE - PostgreSQL Documentation](https://www.postgresql.org/docs/current/sql-altertable.html)
