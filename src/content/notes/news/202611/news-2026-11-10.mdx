## OpenSSHの認証回避脆弱性「SSHole」、修正公開から2日で実被害 muslベースLinuxが標的

JPCERT/CCは11月9日、OpenSSHの認証回避の脆弱性(CVE-2026-123158、通称「SSHole」)について、修正版公開からわずか数日で実際の悪用が確認されたとする注意喚起を発表した。

セキュリティインシデント・脆弱性案件(最大3件枠、本日1件目)。影響を受けるのは、Cライブラリにmuslを使用し、PAM認証が無効化され、パスワード認証が有効で、かつパスワードハッシュ欄が「*」(パスワードログイン無効の印)のアカウントが存在するLinux環境。muslのパスワードハッシュ関数は長すぎるパスワードに対してエラーとして「*」を返すが、OpenSSHがこれを正規のハッシュと誤って一致判定してしまうため、パスワードなしでログインできてしまう。影響を受けるのはOpenSSH 10.6p2より前のバージョンで、AlpineなどクラウドやVPSで広く使われるmuslベースのディストリビューションが対象となる。修正版の10.6p2は11月5日に公開されたが、約4時間後には概念実証コードが公開され、セキュリティ企業GreyNoiseは11月5日以降に悪用の試行を観測、11月7日(修正公開から約40時間後)には侵入・コマンド実行・C2エージェント設置を伴う実際の侵害を確認したという。GreyNoiseは6つのIPから16件の侵害チェーンを観測し、偵察やクラウドメタデータサービスへの問い合わせ、パスワードハッシュ・rootのSSH鍵の読み取り試行、authorized_keysの改変などの挙動を確認。root権限を得た攻撃者がPython製のC2エージェント(コメントが中国語)を設置した例もあったとしている。国内ではAlpine Linuxベースの商用製品の利用が確認されているが、現時点で国内組織における侵害は確認されていない。推奨される対応は、OpenSSH 10.6p2以降への更新または該当環境でのパスワード認証無効化、認証ログでのパスワードハッシュが「*」のアカウントへの不審な「Accepted password for」記録の確認、authorized_keysの不審な変更確認など。

出典: [JPCERT/CC](https://www.jpcert.or.jp/newsflash/2026110901.html) / [BleepingComputer](https://www.bleepingcomputer.com/news/security/hackers-exploit-sshole-openssh-flaw-to-breach-linux-systems/)

## 今日のTips: Reactの`<title>`、どこに書いてもheadへ自動配置されるが同時に複数あると挙動は未定義

React 19以降、コンポーネントのどこで`<title>`をレンダリングしても、Reactは対応するDOM要素を`document.head`内に自動的に配置する。ページ単位のコンポーネントがそれぞれ自分の`<title>`を持てるため、レイアウトをまたいだタイトル管理が書きやすくなる。

```jsx
function ContactUsPage() {
  return (
    <>
      <title>My Site: Contact Us</title>
      <h1>Contact Us</h1>
    </>
  );
}
```

公式ドキュメントは「同時にレンダリングする`<title>`は1つだけにすべき」と明記しており、複数のコンポーネントが同時に`<title>`をレンダリングすると、Reactはそれらすべてを`<head>`に配置してしまい、ブラウザや検索エンジンの挙動は未定義になるという。また`<title>`の子要素は単一の文字列である必要があり、`<title>Results page {pageNumber}</title>`のように式を混ぜると子が配列になってエラーになるため、`` <title>{`Results page ${pageNumber}`}</title> ``のようにテンプレート文字列でまとめる必要がある。

<Tip>`<svg>`内の`<title>`や`itemProp`付きの`<title>`は文書タイトルとして扱われず、headへのホイストも行われない。</Tip>

参考: [`<title>` – React](https://react.dev/reference/react-dom/components/title)
