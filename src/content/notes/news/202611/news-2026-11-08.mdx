## Thinking Machines、新AIモデル「Inkling 2 Small」を発表 知能指数は前世代の2倍以上に

Thinking Machinesは11月5日、新しいAIモデル「Inkling 2 Small」を発表し、同日からAPIサービス「Tinker」で推論と追加学習(ファインチューニング)を利用できるようにした。

AI・LLM動向案件。総パラメーター数594BのMoE(Mixture of Experts)構成で、各トークンの処理には17B分のパラメーターのみを使う。テキストに加え画像入力にも対応する。ベンチマーク「AA Intelligence Index」では31を記録し、前世代の「Inkling Small」の13から大きく向上した。コード関連のベンチマークではDeepSWEが72.1%、FrontierCodeが25.4%。発表では、別モデル(Qwen3.5-4B)のファインチューニングをInkling 2 Smallに任せ、評価プログラムの作成からデータ整備、教師あり学習・強化学習の試行、不具合修正までを一通り担わせた例を紹介している。事前学習から事後学習まで4ビット浮動小数点形式のNVFP4を採用し、事前学習はNVIDIA GB300で68時間、事後学習は9日間・1700万回のロールアウトで行った。モデルの重み全体は、外部の安全性テストを終えたうえで来週公開される予定。

## 今日のTips: NestJSの`ClassSerializerInterceptor`、プレーンオブジェクトを返すと`@Exclude()`が無視される

`ClassSerializerInterceptor`はハンドラーの返り値に`instanceToPlain()`を適用して`class-transformer`のデコレーターを反映するが、公式ドキュメントは「ハンドラーはクラスのインスタンスを返す必要がある」と明記しており、プレーンオブジェクトを返すと`@Exclude()`などは無視される。

```ts
class UserEntity {
  id: number;
  @Exclude() password: string;
}

@UseInterceptors(ClassSerializerInterceptor)
@Get()
findOne() {
  // NG: プレーンオブジェクトなので@Excludeが効かずpasswordが漏れる
  return { id: 1, password: 'secret' };
}
```

対象のエンティティ/DTOクラスの`new`インスタンスとして返せば意図通り除外されるが、サービス層やDBクライアントがプレーンオブジェクトを返す構成では気付きにくい。その場合は`@SerializeOptions({ type: UserEntity })`をハンドラーに付けると、レスポンスが送信前に指定クラスのインスタンスへ変換され、プレーンオブジェクトを返してもデコレーターが適用される。

<Tip>`type`オプションを使う場合、レスポンスの形は戻り値のクラスではなく`type`で指定したクラスが決める。`type`クラスに無いプロパティは変換されずそのままコピーされるため、宣言したプロパティだけを返したいなら`@Expose()`と`excludeExtraneousValues: true`を併用する。</Tip>

参考: [Serialization | NestJS - A progressive Node.js framework](https://docs.nestjs.com/techniques/serialization)
