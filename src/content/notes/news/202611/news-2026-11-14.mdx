## Google、社内コードベースに特化したコーディングAI「GfG」の詳細を公開

Googleの研究者らが10月に発表した論文をもとに、同社の社内専用コーディングAI「GfG」の仕組みが明らかになった。

AI・LLM動向案件。Googleでは社内コードの75%以上がAIで作成・下書きされているが、公開データで学習した汎用LLMは数十億行規模の社内リポジトリ特有のライブラリ・設計パターン・独自言語を理解できない課題があった。GfGは基盤モデルのGeminiを社内データ(約1兆トークン規模)で特化させたもので、完成コードだけでなくコードレビューの指摘・修正差分、社内ドキュメント、ビルドエラー解消までの変更履歴、本番環境の改善履歴なども学習データに含む。社内データ学習で基礎的な推論能力が落ちる「破滅的忘却」を防ぐため、事前学習直前に社内データを注入する手法と汎用データを混ぜて復習させる手法を併用した。社内開発者約2万9000人対象のブラインドA/Bテストでは、Gemini 2.5 Pro比でタスク完了までのやり取り回数が23.1%減少、応答時間が8.9%短縮、生成コードが14日後も修正されず残る割合が16.8%向上した。広告部門の32bit→64bit ID移行では手作業比で所要時間を推定50%削減(変更の80%をAIが作成)、非効率コードを自動検出・最適化する「ECO」は四半期ごとにCPU約50万コア相当を節約しているという。

## 今日のTips: NestJSのSwagger CLIプラグイン、`@ApiProperty()`などのデコレータ記述を自動補完できる

NestJSの`@nestjs/swagger`パッケージには、TypeScriptのコンパイル時にASTを解析してOpenAPIのデコレータを自動生成するCLIプラグインが用意されている。DTOクラスの全プロパティに対し、`@ApiProperty()`の付与、プロパティ名の`?`からの`required`判定、型・`enum`・初期値からの`default`設定を自動化できるため、手書きでは省略できなかった記述を大幅に減らせる。

`class-validator`のデコレータが設定されていれば検証ルールも反映され(`classValidatorShim`オプション)、JSDocコメントから説明文を生成する`introspectComments`オプションもある。

```json
// nest-cli.json
{
  "compilerOptions": {
    "plugins": [{ "name": "@nestjs/swagger" }]
  }
}
```

<Note>自動生成はファイル名が既定の`.dto.ts`/`.entity.ts`の場合のみ対象になる(`dtoFileNameSuffix`等で変更可能)。実行時バリデーションは引き続き`class-validator`のデコレータが担うため、`@IsEmail()`等は残す必要がある。SWCビルダーを使う場合は`nest start -b swc --type-check`などの追加設定が必要。</Note>

参考: [NestJS Documentation — OpenAPI CLI Plugin](https://docs.nestjs.com/openapi/cli-plugin)
