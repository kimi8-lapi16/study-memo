## MCP公式Ruby SDKが「Tier 1」に到達 全プロトコル機能をフルサポート

Linux Foundation傘下でMCP(Model Context Protocol)の仕様策定を進めるAgentic AI Foundation(AAIF)は、公式のMCP Ruby SDKが仕様を完全にサポートする最上位区分「Tier 1」に到達したと発表した。

開発ツール・言語・OSS動向案件。AAIFはSDKを3段階で区分しており、Tier 1は全プロトコル機能をフルサポート、Tier 2は継続的にメンテナンスされ完全サポートを目標とする段階、Tier 3は実験的・部分実装または特定用途向けという位置づけ。Ruby SDKは2026年7月にバージョン1.0に達した時点ではTier 2だったが、今回サーバー・クライアント双方の実装が仕様に準拠したと確認され、ステートレス接続などの最新機能を含め、ドキュメント上非推奨とされる2機能を除くすべてに対応した。これにより、Ruby開発者はMCPベースのアプリケーションをより安心して本番環境へデプロイできるとしている。Tier 1のSDKはこれまでTypeScript・Python・C#・Go・Rustが対応しており、Rubyが新たに加わった。Ruby SDKチームは、2027年3月末を目標とする次期MCP仕様への対応も継続して進める方針を示している。

## 今日のTips: Prismaの`findUniqueOrThrow`、レコードが無いとエラーを投げる代わりに`$transaction`配列実行では使えない

`findUniqueOrThrow()`/`findFirstOrThrow()`は、対象レコードが見つからない場合に`null`を返す通常の`findUnique`/`findFirst`とは異なり`PrismaClientKnownRequestError`を投げる。戻り値の型も非nullableになるため、後続処理で`null`チェックを省きたい場面で使われる。

```ts
// 通常版: 見つからなければ null
const user = await prisma.user.findUnique({ where: { id } });

// OrThrow版: 見つからなければ PrismaClientKnownRequestError
const user2 = await prisma.user.findUniqueOrThrow({ where: { id } });
```

公式ドキュメントは、この2メソッドが`$transaction`の配列実行(複数クエリを配列で渡す逐次実行)と組み合わせられないと明記している。配列実行中にエラーが発生しても配列内の他の操作はロールバックされないため、見つからない可能性があるレコード取得をロールバック込みで扱いたい場合はインタラクティブトランザクション(コールバック形式の`$transaction`)を使う必要がある。

<Tip>配列形式の`$transaction`はバッチ的な一括実行であり、個々の操作の成否にかかわらず全体をアトミックに扱う保証はこのケースでは崩れる。確実にロールバックさせたいなら`prisma.$transaction(async (tx) => { ... })`形式に変更する。</Tip>

参考: [Prisma Client API reference | Prisma Documentation](https://www.prisma.io/docs/orm/reference/prisma-client-reference#finduniqueorthrow)
