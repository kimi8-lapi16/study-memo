## GCC開発チーム、法的に重要なAI生成コードの貢献を原則拒否する方針を採択

GNUのGCC開発チームは、著作権・ライセンス上「法的に重要」とみなされるAI生成コードの貢献を原則として受け付けない方針を公式に採択した。

開発ツール・言語・OSS動向案件。GNUのメンテナー向けガイドラインは「法的に重要な貢献」を約15行を超えるコード・文章の貢献と定義しており、これを超えるLLM生成コンテンツやその派生物を含む貢献は拒否される。15行以下の小規模な貢献やテストケースは例外的に受け入れられるが、その場合もコミットメッセージへの「Assisted-by:」タグの明記と、人間による内容の理解・説明責任が必須とされる。個人利用や研究・デバッグ目的でのAI利用は対象外だが、その成果物をプロジェクトに取り込む場合は同方針が適用される。

## 今日のTips: TypeScriptの超過プロパティチェックは、オブジェクトリテラルを直接渡した時にしか働かない

TypeScriptの「超過プロパティチェック（Excess Property Checks）」は、オブジェクトリテラルを関数呼び出しや変数宣言の場で直接渡したときだけ働く仕組みで、いったん変数に代入してから渡すとチェックをすり抜ける。

```ts
interface Point {
  x: number;
  y: number;
}

function draw(p: Point) {}

draw({ x: 1, y: 2, z: 3 });
// Error: Object literal may only specify known
// properties, and 'z' does not exist in type 'Point'

const obj = { x: 1, y: 2, z: 3 };
draw(obj); // エラーにならない
```

<Tip label="▶ 補足">
`obj`が`draw`に代入される時点では超過プロパティチェックの対象にならないため、余分な`z`プロパティが混入していても素通りする。タイポしたプロパティ名に気づきたい場合は、オブジェクトを直接リテラルで渡すか、`obj`の型を明示的に注釈しておくとよい。
</Tip>

参考: [TypeScript Handbook: Excess Property Checks](https://www.typescriptlang.org/docs/handbook/2/objects.html)
