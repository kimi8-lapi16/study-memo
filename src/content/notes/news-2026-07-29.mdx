</Note>

## 今日のTips: NestJSで素のErrorをthrowすると、詳細が握りつぶされて500 Internal server errorに丸められる

NestJSの組み込みグローバル例外フィルターは、`HttpException`系ではない一般的なJavaScriptの`Error`を検知すると、内容によらず`{"statusCode": 500, "message": "Internal server error"}`という定型レスポンスに丸めてしまう。デバッグ中に投げたエラーメッセージがそのままクライアントに返ってくると思い込んでいると、思わぬところで詳細情報が消える。

```ts
@Get(':id')
findOne(@Param('id') id: string) {
  // NG: 詳細メッセージは握りつぶされ常に500 "Internal server error"に
  if (!found) throw new Error(`user ${id} not found`);

  // OK: HttpException系ならステータスとメッセージがそのまま返る
  if (!found) throw new NotFoundException(`user ${id} not found`);
}
```

<Tip label="▶ 補足">
例外オブジェクトが`statusCode`と`message`のプロパティを持っていれば、素のErrorでなくても正しく反映される。独自エラークラスを使う場合はこの2つを持たせるか、`HttpException`を継承するのが手堅い。
</Tip>

参考: [NestJS Exception Filters](https://docs.nestjs.com/exception-filters)
